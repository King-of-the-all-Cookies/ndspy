Приложение: структура SDAT

==========================



На этой странице объясняется, как файлы внутри звукового архива *SDAT* связаны

между собой. Здесь нет ничего, специфичного для ndspy, а значит, если вы уже

знаете организацию *SDAT*, можете пропустить текст.



.. contents:: :local:



Обзор

-----



В большинстве игр для Nintendo DS все звуковые данные собраны в одном файле *SDAT*

(часто его называют *sound_data.sdat* или как-нибудь похоже): музыка и звуковые

эффекты лежат вместе. Некоторые треки записаны как «стримы» (вроде *mp3* или

*wav*), но обычно, чтобы экономить память, почти вся музыка хранится в форме

«последовательностей» (аналогично `midi-файлу

<https://en.wikipedia.org/wiki/MIDI>`_). Инструменты для проигрывания

последовательностей содержат данные *SWAV* и метаданные. Звуковые эффекты тоже

представлены последовательностями, но обычно используют собственные уникальные

«инструменты» и зачастую состоят из одной ноты.



*SDAT*\: общий контейнер

-----------------------



Файл *SDAT* («sound data») содержит множество файлов *SWAR*, *SBNK*,

*SSEQ*, *SSAR*, *Sequence player*, *STRM*, *Stream player* и/или *Group*. Иногда

архив хранит имена файлов, но это не обязательно: их могут опустить, чтобы

сэкономить пространство. Игра обычно обращается к файлам по номерам ID, так что

отсутствие имени — лишь неудобство.



Вопрос «зачем *SDAT* содержит файлы, если он мог бы просто хранить всё напрямую?» 

решается тем, что компоновка позволяет загружать группы связанных звуков

сразу. Например, нет смысла загружать инструменты, используемые в боевой музыке,

если игра сейчас отображает главное меню.



*SWAV*\: короткий стрим

-----------------------



Файл *SWAV* («sound wave») — это короткий монофайл, который можно зациклить. Чаще

всего он соответствует одной ноте инструмента или звуковому эффекту. Хотя

*SWAV* содержит сырой звук, игры не ищут его напрямую при воспроизведении эффекта.

Вместо этого они ссылаются на записи последовательностей внутри файлов *SSAR*,

которые проигрывают ноты через инструменты с нужными *SWAV*.



Обычно *SWAV* находятся в рамках *SWAR*.



*SWAR*\: папка *SWAV*

--------------------



Файл *SWAR* («sound wave archive») — это по сути папка *SWAV*-файлов. Внутри

они не имеют имен и обращаются по номеру.



Файлы *SBNK* используют *SWAR*.



*SBNK*\: банк инструментов

--------------------------



Файл *SBNK* («sound bank») хранит набор инструментов, доступных для последовательности.

Он может указать до четырёх ID *SWAR*, которые содержат сэмплы, нужные

инструментам. Инструмент внутри *SBNK* выбирает *SWAR*, указывая номер одного из

этих ID (0, 1, 2 или 3).



Существует три типа инструментов, и все они опираются на «определения нот»:



Определение ноты

++++++++++++++++



Определение ноты задаёт одну ноту, которую умеет играть инструмент. Оно содержит:



*   Значение типа, определяющее, будет ли нота проигрываться через *SWAV*, через квадратную волну или через белый шум [1]_.

*   Если тип указывает воспроизведение *SWAV*: номер *SWAR* (индекс от 0 до 3 в списке ID в *SBNK*) и номер *SWAV* внутри него.

*   Саму ноту в виде числа (например, 60 — до малой октавы, 74 — ре большой, 46 — ля).

*   Технические параметры: «attack rate», «decay rate», «sustain rate», «release rate» и «pan».



Хотя определение описывает только одну ноту (скажем, до средней октавы), игры

могут и используют одно определение для множества нот. Для этого скорость

воспроизведения сэмпла меняют вручную, чтобы достичь нужной высоты. Расчёты

делаются автоматически, вам не нужно заниматься этим вручную.



.. [1]

    Если определение принадлежит однонотному инструменту, у него нет собственного

    значения типа — используется тип самого инструмента. В других случаях

    определение имеет свой тип, как ожидается. ndspy скрывает эту деталь.



Однонотный инструмент

+++++++++++++++++++++



Простейшая разновидность инструмента. Содержит одно определение ноты и ничего

лишнего.



Не думайте, что инструмент может играть только одну ноту. Игра может

изменять высоту, ускоряя или замедляя воспроизведение.



Инструмент диапазона

+++++++++++++++++++++



Такой инструмент объявляет диапазон нот (например, от 60 до 72) и содержит

по одному определению для каждой ноты. Номера нот в определениях могут не

совпадать с позиции в диапазоне.



Региональный инструмент

++++++++++++++++++++++++



Инструмент этого типа объявляет до восьми неперекрывающихся «регионов», которые

вместе покрывают диапазон от 0 до 127. В каждом регионе есть одно определение

ноты, а игра генерирует остальные ноты, используя его.



*SSEQ*\: последовательная музыка

-------------------------------



Файл *SSEQ* («sound sequence») — это один трек последовательной музыки. Он

содержит:



*   ID файла *SBNK*;

*   технические параметры: громкость, «channel pressure», «polyphonic pressure», «play»;

*   список событий.



События похожи на события *midi*-файлов: это команды, описывающие, как

проигрывать трек. Они содержат ноты, паузы, команды смены инструментов,

запуска нескольких дорожек одновременно, прыжки, петли и многое другое.

События могут иметь параметры, зависящие от конкретного типа.



*SSAR*\: архив звуковых эффектов

--------------------------------



Файл *SSAR* («sound sequence archive») содержит набор звуковых эффектов. Каждый

эффект включает всю метаинформацию *SSEQ*, причем у них общий пул событий.



Эффекты звучат иначе, потому что начинаются с разных позиций в пуле событий.

Чаще всего они не перекрываются, используя события, которые завершают выполнение.

Похожие эффекты иногда делят события, прыгая между ними. Это делает редактирование

отдельного эффекта немного сложнее, так как можно нечаянно изменить другие.



*Sequence player*\: ограничения последовательностей

---------------------------------------------------



Sequence player задаёт максимальное число одновременно играющих последовательностей и объём памяти, выделяемой под их данные. Также он перечисляет аппаратные звуковые каналы, которые разрешено использовать, чтобы не мешать стримам.



Некоторые игры используют сразу несколько sequence player-ов. В таком случае

каждому из них отводится небольшое число последовательностей, объём памяти

ставится в ноль (чтобы вычисляться во время выполнения), и список каналов

оставляется пустым (также для вычисления во время работы).



*STRM*\: многоканальный стрим

-----------------------------



Файл *STRM* («sound stream») — это *SWAV*, поддерживающий несколько каналов.

Если *SWAV* используют для сэмплов инструментов, то *STRM* служит для

полноценных музыкальных дорожек. Он существует сам по себе и не ссылается на

другие файлы.



*Stream player*\: разрешённые каналы для стримов

-----------------------------------------------



Stream player перечисляет аппаратные каналы, на которых можно проигрывать

*STRM*. Это нужно, чтобы не мешать последовательностям, проигрываемым

параллельно.



Например, значение `[6, 7]` означает: первый канал первого стрима должен

идти на аппаратный канал 6, второй — на 7 (обе нумерации начинаются с нуля).

Попытка воспроизвести более двух каналов *STRM* в этом случае будет

прекращена.



*Group*\: группа элементов

--------------------------



Group — это коллекция ID объектов, существующих в другом месте *SDAT*. Эти

объекты могут быть разного типа. Игры используют группы, чтобы собирать файлы,

которые должны загружаться одновременно. Иногда их называют «наборы звуков».
